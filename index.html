Fracturius is a 2D game-engine project designed around flexible tools, expressive physics, and intelligent gameplay. Its goal is to bring simulation, game development, and neural-network experimentation into one connected environment.

In development — systems and architecture are being established.
01 / The idea

One environment. Connected systems.

Fracturius is intended to make it possible to build a 2D game, simulate how its world behaves, and experiment with AI that can learn inside that world. Rather than treating those capabilities as unrelated add-ons, the engine is being designed so they can communicate through clear interfaces.

Design principles

Modular by design. Each major subsystem should have a defined responsibility and a usable interface.

Physics-aware. Game objects, collisions, and simulation data should work together instead of being isolated features.

Built to experiment. Developers should be able to inspect behavior, tune systems, and test ideas without fighting the engine.

Expandable. Optional tools should add capability without making the core runtime unnecessarily complicated.

02 / Engine systems

Purpose-built for 2D development.

The engine is planned as a collection of cooperating modules. The boundaries below describe the intended architecture, not a claim that every feature is already implemented.

PH

Physics

Rigid-body motion, collision handling, material behavior, constraints, and experimental structural simulation.

RE

Rendering

A 2D renderer for sprites, textures, cameras, animation, tilemaps, particles, and visual effects.

NX

Nexius neural tools

A planned toolkit for constructing, training, inspecting, and using neural networks in game projects.

SC

Scenes and entities

Organize game worlds, objects, components, and reusable scene data.

IO

Input and audio

Handle player controls, device input, sound effects, and music through consistent interfaces.

AS

Assets and tools

Load and organize project resources, with room for debugging and visual editing tools.

03 / Physics foundation

Building on FrameLabs.

Physics is a central part of Fracturius. The project draws on the work and experimentation behind FrameLabs 2 and FrameLabs 3. The long-term goal is to consolidate the useful ideas into a reusable physics subsystem designed for the needs of a general-purpose 2D engine.

What the physics layer is intended to handle

Rigid bodiesCollision detection MaterialsGravity FrictionConstraints Structural stressDestruction experiments

These are development targets. The implementation will be documented as each capability is integrated and tested.

How the systems connect

Game worldEntities hold transforms, colliders, and physics properties.
↓
Physics interfaceThe engine passes bodies, forces, and simulation settings to the physics layer.
↓
Simulation stepPhysics calculates motion and contacts, then exposes results to the engine.
↓
Game and rendererUpdated transforms and events drive visuals, gameplay, and AI inputs.
04 / Intelligent gameplay

Neural networks belong in the workflow.

Fracturius is planned to include a neural-network development toolkit built around Nexius. The aim is to make it easier to create networks, connect them to game data, train them, and understand what they are doing.

Planned neural workflow

Design: define network layers, neuron counts, and activation functions.

Connect: feed game-state values into network inputs and route outputs to game logic.

Train: experiment with supervised learning, reinforcement learning, and evolutionary methods.

Inspect: visualize activations, training progress, rewards, and network structure.

Training methods and acceleration options will be added incrementally and clearly documented.

05 / How it works

From project setup to a running game.

The intended development workflow keeps game content separate from the engine's underlying systems.

Create a project

Set up a game and organize its scenes, assets, and configuration.

Build the world

Add entities, components, sprites, and gameplay behavior.

Configure simulation

Give objects physics properties and define how they interact.

Run and iterate

Test the game, inspect behavior, and refine systems or AI.
